# Tier: Enterprise (20+ people)

## Agent Window Count
Organized by team/domain. Each sub-team gets its own set of agents.

## File Organization
```
PROJECT-ROOT/
  PLAN.md                          # Top-level epic/feature breakdown
  BUG-BOARD.md                     # Cross-team bugs
  TEAM-PLANS/
    team-auth/PLAN.md              # Auth team's plan
    team-auth/BUG-BOARD.md
    team-dashboard/PLAN.md         # Dashboard team's plan
    team-dashboard/BUG-BOARD.md
    team-api/PLAN.md               # API team's plan
    team-api/BUG-BOARD.md
  INTERFACES/
    contracts.md                   # Versioned API contracts
    ownership.md                   # File/resource ownership registry
    transfer-log.md                # Audit trail of ownership transfers
  STATUS/
    weekly-report.md               # Consolidated status summary
```

## Concurrency
Distributed locking with ownership registry. Every file path is
registered to an owning team. Cross-team file changes require
explicit transfer of ownership.

See `references/concurrency/ownership.md` for details.

## Ownership Registry Format
```markdown
| File Pattern | Owner Team | Approver | Contact |
|---|---|---|---|
| src/auth/** | auth-team | Alice | @alice |
| src/api/** | api-team | Bob | @bob |
| src/shared/** | platform-team | Carol | @carol |
| *.sql | dba-team | Dave | @dave |
```

## Coordination Structure
- Human architects define ownership boundaries in ownership.md
- Team leads update their team's PLAN.md weekly
- Cross-team bugs go to top-level BUG-BOARD.md
- Interface contracts are the single source of truth for APIs
- Status reports are generated by reading all TEAM-PLANS

## Transfer Protocol
When Team A needs to modify a file owned by Team B:
1. Team A writes a "modification request" to BUG-BOARD.md with
   tag [TRANSFER] specifying the file and reason
2. Team B's approver reviews within SLA
3. If approved: Team B makes the change, or transfers ownership
4. If rejected: Team A must find an alternative approach

## Status Reporting
Weekly: coordinator reads all TEAM-PLANS and STATUS files to
produce a consolidated report.

Agent prompt:
"Read all files under TEAM-PLANS/ and STATUS/, produce a
consolidated status report with: completed this week,
planned next week, blockers, cross-team dependencies."
